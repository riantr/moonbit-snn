# split_tests — move `*_test.mbt` out of the root package so `moon test` can run

## Why this exists

`moon test` on the root package fails:

```
CreateProcessW: 文件名或扩展名太长。   (exit 1)
```

That is the Win32 32767-character command-line limit. Isolating the stage:

| command | result |
|---|---|
| `moon check --target native` (516 files) | **0 errors** — moonc is fine |
| `moon test` (root package) | `CreateProcessW` |
| `moon test ./tests/wave1` (27 files, as a sub-package) | **216/216 passed, exit 0** |

So the failure lives entirely in the C backend / link stage, and only for the
root package's **test target**. The fix is therefore not to shrink the
implementation — it is to stop asking the root package to host the tests.

Note what this refutes: a sub-package that is generated C of **957 KB**
(`wave1.blackbox_test.c`) compiles and links fine, while the root package's
**203 KB** test C file does not. "The generated C is too big" is not the
mechanism, and reasoning from C-file size sends you down the wrong path.

## The mechanism

Per-directory manifest named `moon.pkg` (not `moon.pkg.json`):

```
import {
  "riantr/snn_mbt",
}

options(
  "is-test": true,
)
```

The parent is imported **by module name**; symbols are then reached as
`@snn_mbt.Graph::zeros`, `@snn_mbt.Xoshiro::default`, … No `moon.work`
workspace is involved, and no `pkg.generated.mbti` regeneration is required.
(`moon work init/use/sync` manages *separate modules*, each with its own
`moon.mod`; using it for an in-module split buys nothing and adds a version
contract nobody maintains.)

## How to run

```powershell
cd mbt
moon test .\tests\wave1 --target native
```

Cold build from a wiped `_build/native`: **~4 s** for 27 files, parent package
included.

## The rewriter

`split_qualify.py` prefixes every parent-package symbol with `@snn_mbt.`, using
`mbt/pkg.generated.mbti` (generated by `moon info`) as the allow-list.

**Do not derive the allow-list from the sources with a `^\s*` regex.** An early
attempt did, and reported 233/234 test files as untouchable — the artifact was
that `^\s*` matches indented `impl`-block methods, so `i`, `k`, `mut`, `empty`
and other locals were classified as top-level definitions. The `.mbti` is the
compiler's own answer to "what is public" and needs no interpretation.

It also has to handle `pub(all)` and `pub(open)`: matching bare `pub` missed
100 of the 413 type declarations.

## Four bugs the gate had to be able to catch

All four were silent — the file compiled, just not into the intended program.
`qualify()` now asserts the splitter is a lossless partition of its input
before it rewrites anything.

1. **String interpolation is code.** `fail("... \{gelu_grad(1.0F)}")` held a
   real expression inside a string literal; skipping strings whole left it
   unbound. `\{expr}` is now re-entered as a code segment.
2. **The interpolation escape was destroyed.** Emitting the `{` as code but
   dropping the preceding `\` degraded `\{x}` to `{x}`.
3. **The matching `}` was emitted twice**, so the round trip grew by 1 byte
   per interpolation.
4. **A string's opening quote was swallowed.** `lit = i` sat *after* `i += 1`,
   turning every `test "name" {` into `test name" {`. This surfaced as a parse
   error in an unrelated file, ~600 lines away from the defect.

## Layout of the 234 test files

- 207 still in the root package (not yet migrated)
- 27 in `tests/wave1`, 216 test blocks, all passing

Wave 1 covers neurons, STDP/STP, spiking connections, analysis, the DL
primitives, two optimizers, one stimulus, units and time — chosen for spread,
not for size, so the rewriter's failure modes show up in every category.

## Does the test sub-package bloat what `moon publish` ships?

`moon package` (not `moon publish` — it writes the archive locally and does not
touch the network) answers this directly:

```
moon package --list          # the manifest, on stderr, after ~4 MB of warnings
moon package                 # -> _build/publish/riantr-snn_mbt-0.155.0.zip
```

Measured on the wave-1 archive: **760 entries, 1.25 MB compressed, 3.78 MB
uncompressed**, of which `tests/wave1` is 28 entries / 145.6 KB.

**`is-test: true` does not exclude a package from the archive.** The sub-package
is shipped. That turns out to be the right outcome rather than a problem:

- The 27 test files were already in the archive (as root-package files). Wave 1
  *relocated* them. The net growth across the whole set is **+6,340 bytes
  (+4.6%)** on the test payload, which is just the `@snn_mbt.` prefixes —
  +0.5% of the archive.
- Shipping them is a feature: extracting the published zip and running
  `moon test ./tests/wave1` gives **216/216 passed, exit 0** against the
  published artifact, not against the working tree.

So a consumer of `riantr/snn_mbt` can run part of the suite themselves. Nothing
to exclude, and nothing to fix.

Three unrelated hygiene items the same listing exposed, all pre-existing and
all cosmetic:

| file | KB | note |
|---|---|---|
| `quaresima_2024_updown.jl` | 0.8 | a Julia reference file tracked inside the MoonBit package |
| `testdata/moon_mod_v0.13.2_backup.tmp` | 1.0 | a stale backup |
| `examples/**/pkg.generated.mbti` | 12.6 | 77 generated interface files |

Reading the list: PowerShell's `1>` redirect writes **UTF-16LE**, so pipe the
output through Python (decode `utf-16`) rather than reading the file as UTF-8 —
otherwise every line looks like mojibake and the parse finds nothing.
